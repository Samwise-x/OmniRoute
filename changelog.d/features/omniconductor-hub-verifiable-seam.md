- **feat(conductor):** the Omniconductor Hub is now provable rather than asserted — `npm run verify:conductor` boots real Hub/Faro/Runner processes and writes a GO/NO-GO report to `docs/ops/OMNICONDUCTOR_EVIDENCE.md`, `npm run verify:conductor:docker` builds and brings up the Compose stack on a Docker host (and fails loudly where there is no engine), plus `test:conductor:contract` drives OmniRoute's production route handlers against a real Hub. New `tests/unit/conductor-runtime-guards.test.mjs` (10 cases) and `tests/unit/conductor-opencode-seam.test.mjs` (6 cases) cover the refusal, isolation and harness-contract paths that had none, and a `OmniConductor Hub (runtime evidence)` CI job runs all of it.
- **fix(conductor):** four defects a live deployment exposed and no test caught. The Agent Card advertised **no fleet at all** — `fleetSkills` required `models: [{id}]` while the bundled Hub sends plain strings, so the whole skill list was dropped; the Runner handed OpenCode **no gateway config** (its per-task HOME is empty), so self-hosted OpenCode fell back to its own hosted catalog; a `<prefix>/*` capability such as `omniroute/*` was compared as a literal string, leaving every gateway-pinned task queued forever; and a task whose CLI/model a Runner could not serve threw outside the error handler and killed the Runner process instead of failing that one task.
- **feat(conductor):** OpenCode is the reference self-hosted harness for the Runner seam. With `OMNIROUTE_BASE_URL` set the Runner seeds a per-task `opencode.json` whose only provider is the operator's gateway, with the key referenced as `{env:OMNIROUTE_API_KEY}` so it is never written to disk, the workspace or the patch; `OPENCODE_MODEL` supplies the default `--model`, and a bare (non-`omniroute/`) model is refused unless `RUNNER_OPENCODE_ALLOW_HOSTED_MODELS=true`, so a self-hosted deployment cannot silently route work to OpenCode's catalog.
- **feat(conductor):** the Hub is now *operable*, not just functional. `GET /v1/tasks` is keyset-paginated (`limit`/`cursor`/`status`/`mode`, capped at 200) while still returning a plain array when unpaged; terminal tasks are pruned by age (`CONDUCTOR_TASK_RETENTION_MS`, default 7 days) and by count (`CONDUCTOR_MAX_TASKS`); `mode` is a closed set (`solo|council`) at both the Hub and the OmniRoute route; `POST /v1/tasks/:id/retry` re-queues a terminal task **in place** (same id, prior outcome kept in `retry_history`, capped by `CONDUCTOR_MAX_TASK_RETRIES`); and `POST /v1/runners/deregister` lets a Runner hand its in-flight work back on graceful shutdown instead of stranding it until the heartbeat TTL. `GET /metrics` reports queue depth against live fleet capacity, oldest-queued age, and the active retention settings.
- **feat(conductor):** least-privilege principals. Optional `CONDUCTOR_RUNNER_TOKEN` and `CONDUCTOR_READONLY_TOKEN` scope what each party may do — a Runner can register/heartbeat/claim/deregister/report and *nothing else*, so a compromised Runner can no longer create, cancel or retry tasks fleet-wide. Both unset preserves the original single-secret behaviour, so adoption is incremental.
- **feat(conductor):** the dashboard consumes the Hub's events instead of poll-discarding them. `GET /api/conductor/stream` forwards the Hub's SSE frames (ids preserved, `Last-Event-ID` resume, server-side token), and the panel drops its 5 s poll to a 60 s safety net while showing `live`/`polling`. Task detail gained a retry action.
- **fix(conductor):** two facts about the pinned OpenCode CLI corrected against the binary (`opencode-ai` 1.19.3) rather than assumed: `--auto` **is** part of the release and is **required** for a TTY-less task (without it the run blocks on an approval prompt until timeout), and pointing the CLI at a gateway is **not** enough — it fetches `/v1/models` successfully and still fails `ProviderModelNotFoundError`, so the seeded config must declare a `provider.omniroute.models` entry per advertised model. `tests/unit/conductor-opencode-real.test.mjs` (`npm run test:conductor:opencode`) drives the real pinned binary through a real Hub and Runner; a gateway that answers `stream: true` with a non-streamed body causes unbounded retries, which that test now pins down.
- **fix(conductor):** a Runner-reported harness version is now accepted only when it matches a version pattern. A wrapper that ignores `--version` and prints its usual chatter exits 0 too, and the evidence report was recording that chatter as the OpenCode version; the fleet view now also advertises the real version so an operator can see which binary a Runner has.
